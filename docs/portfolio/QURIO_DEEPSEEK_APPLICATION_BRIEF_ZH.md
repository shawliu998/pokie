## 一页项目摘要

### 一句话

Qurio 是一个 AI 原生量化研究工作台：一个受约束、可验证的 Research Agent
能够制定研究计划、调用工具完成实验、根据证据修正，并在密封留出集失败时给出
“继续研究”，而不是包装成成功策略。

### 我想解决的问题

通用 Agent 很容易生成看似合理但无法复核的结论。量化研究又特别容易出现指标
口径不一致、过度拟合和测试集泄漏。因此我把 Agent 的自主性限制在研究决策层：

- 模型决定下一步研究动作；
- 注册工具限制 Agent 能做什么；
- 确定性内核统一计算全部指标；
- 训练阶段结束后只打开一次密封留出集；
- 每次实验、失败、修复和选择理由都进入结构化 Research Memory。

### 最能说明问题的案例

一次真实运行使用了 548 根 Kraken `BTCUSD · 4h` 收盘 K 线和 DeepSeek
`deepseek-v4-flash`，Mock 回退关闭。

Agent 先比较 A、B 两个候选，然后提出 C。C 的第一次工具调用违反了策略家族与
调整动作的合同，被系统拒绝；下一轮模型只修改了错误字段并成功完成实验。

训练指标排序为 C、B、A，但 C 的训练交易数为零。确定性的最小交易证据规则没有
盲从排名，而是选择 B。B 随后在新鲜密封留出集上失败，所以最终结论是
`revise_research`。

这个案例没有证明 alpha，却证明了系统能够：

- 让 Agent 的错误可见并可修复；
- 把模型判断与指标计算分开；
- 不把零交易候选包装成优秀策略；
- 不因留出集失败而反复打开测试数据。

### 工程边界

- 桌面端：Tauri + React。
- 本地服务：FastAPI + Research Agent worker。
- 决策模型：DeepSeek 或受控的 OpenAI-compatible Provider。
- 数据：不可变数据版本，支持 CSV、Binance、Kraken 和受约束的 Nasdaq 路径。
- 验证：Python 合同/集成/安全/评测测试、Vitest、Playwright、Cargo 和 macOS
  原生门禁。
- 明确不做：Broker、实盘交易、任意 Python、Agent 市场和多 Agent 编排。

## 30 秒版本

我做了一个叫 Qurio 的 AI 原生量化研究工作台。它不是聊天套壳，而是让一个
Research Agent 在批准的计划和工具预算内做候选实验，确定性内核负责全部指标。
我最想展示的不是一次赚钱回测，而是一次真实 DeepSeek 运行：Agent 的工具调用
先被拒绝、随后完成窄修复，最后候选仍然在密封留出集失败，系统诚实地给出
“继续研究”。我希望用这个作品说明，我关心的不只是模型能生成什么，也关心怎样
把自主决策变成可验证、可复盘的产品。

## 90 秒版本

Qurio 的起点是一个很具体的问题：如果让大模型参与量化研究，怎样避免它只生成
漂亮的策略描述和回测数字？

我的处理方式是把模型和确定性系统分工。用户先选择保留的数据并批准研究计划；
一个 Research Agent 只能调用七个注册工具来生成候选、运行实验、比较和调整；
所有收益、回撤、交易和留出集结果都由同一个确定性内核计算。

在主案例中，系统使用真实 Kraken BTCUSD 四小时数据和 DeepSeek。Agent 做了
A/B 两个候选后，根据训练证据提出 C。C 的第一次工具调用违反合同，被服务端
拒绝；模型下一轮只修正了错误的 replan action，没有改变其他参数。训练排序是
C、B、A，但 C 没有产生交易，所以确定性证据规则选择 B，而不是机械选择第一名。

最后系统只打开一次密封留出集，B 失败。Qurio 没有把这次运行标记成系统失败，
也没有继续对测试集调参，而是保留完整证据并建议 revise research。

这件事对我最重要的地方是：Agent 的价值不只是“能行动”，而是行动边界、错误、
修复和停止理由都能被人理解和验证。

## 高频追问

### 为什么不用多 Agent？

当前核心问题是让一条证据 → 调整 → 决策链可理解。一个 Agent 加专业工具更容易
归因，也便于控制预算。只有当独立 specialist loop 能在相同预算下稳定提高结果，
我才会引入多 Agent。

### 如何避免 holdout 泄漏？

候选生成、调整和比较只使用训练分区。最终候选冻结后才执行一次密封留出集评估；
holdout 结果不能回流到同一研究版本继续调参。继续研究会创建有清晰 lineage 的
新版本。

### 为什么相信回测指标？

不要求相信模型。模型只选择研究动作，指标由唯一确定性计算路径产生，使用固定的
执行时点、成本和候选 canonical key；UI、比较和证据导出都读取同一份结果。

### Agent 调用工具失败怎么办？

工具层返回有类型的错误和被拒参数。下一轮模型获得这份反馈；系统同时限制修复
预算、拒绝重复无效动作，并记录 correction delta。主案例中只发生了一次失败，
下一轮只改动了错误的 replan action。

### 这个项目目前最大的不足是什么？

目前证明的是单次完整工程边界，不是通用 Agent 能力或用户需求。下一步最有价值的
工作是冻结一组研究任务，对 DeepSeek 与确定性基线比较任务完成率、工具调用有效率、
修复率、重复候选率、成本和失败类型，而不是再增加新页面。
